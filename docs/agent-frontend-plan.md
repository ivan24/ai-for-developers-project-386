# План разработки Frontend-приложения для бронирования (для AI-агента)

**Контекст задачи:**
Необходимо разработать SPA (Single Page Application) для сервиса бронирования календаря. Приложение должно взаимодействовать с REST API (по контракту `docs/calendar.tsp`). 
Авторизации нет. Есть две роли (маршруты): Владелец (`/owner/*`) и Гость (`/public/*` или корень).

**Технологический стек (Свежие версии 2026 года):**
- Фреймворк: **React 19**, **TypeScript**
- Сборщик: **Vite 8**
- Стилизация: **Tailwind CSS**, **shadcn/ui**
- Маршрутизация: **React Router v7**
- Состояние и API: **TanStack Query v5** (React Query)
- Мок-сервер API: **Prism** (с предварительной компиляцией TypeSpec в OpenAPI)
- Инфраструктура: **Docker**, **Docker Compose**, **Make**

---

## Шаг 1: Инфраструктура (Docker и Make)
**Задача:** Настроить контейнеризацию и базовые команды управления.
1. В корне проекта создайте папку `docker/`. В ней создайте Dockerfile для фронтенда (`Dockerfile.frontend`) и Dockerfile для мок-сервера API (`Dockerfile.api`).
2. В `Dockerfile.api` добавьте шаги: установка `@typespec/compiler` и `@typespec/openapi3`, компиляция файла `docs/calendar.tsp` в `openapi.yaml`, и запуск `prism mock -h 0.0.0.0 openapi.yaml`.
3. В корне проекта создайте `docker-compose.yml`, который поднимает два сервиса: `frontend` (на порту 5173, монтируя локальные файлы) и `api-mock` (на порту 4010).
4. В корне создайте `Makefile` со следующими командами:
   - `make up` — запуск `docker-compose up -d --build`
   - `make down` — остановка контейнеров
   - `make logs` — просмотр логов
   - `make sh-frontend` — вход в shell фронтенда для установки пакетов.

## Шаг 2: Инициализация Frontend-приложения и UI-библиотеки
**Задача:** Развернуть базовый код React и настроить UI.
1. Инициализируйте проект React + Vite + TypeScript в папке `frontend/` (или прямо в корне, если папка не предусмотрена; предпочтительно `frontend/`).
2. Установите Tailwind CSS и настройте `tailwind.config.js`.
3. Инициализируйте `shadcn/ui` (через CLI или вручную).
4. Добавьте базовые компоненты: `Button`, `Card`, `Input`, `Dialog`, `Calendar`, `Form`, `Toast` (для уведомлений об ошибках/успехах).
5. Установите `react-router` и `@tanstack/react-query`.

## Шаг 3: Маршрутизация и Layouts
**Задача:** Настроить структуру страниц.
1. Создайте `RootLayout` (общая обертка с навигацией по демо-ролям) и настройте роутер.
2. Подготовьте пустые страницы-заглушки:
   - **Гость:**
     - `/` — Список доступных типов событий.
     - `/book/:eventTypeId` — Выбор даты, слота и форма бронирования.
     - `/booking/manage` — (Опционально) просмотр/отмена брони по токену.
   - **Владелец:**
     - `/owner` — Дашборд/Профиль владельца.
     - `/owner/event-types` — Управление типами событий (CRUD).
     - `/owner/bookings` — Предстоящие бронирования всех типов.

## Шаг 4: API Клиент и Хуки (TanStack Query)
**Задача:** Реализовать слой данных по контракту TypeSpec.
1. Настройте базовый экземпляр `axios` или `fetch` для обращения к `http://localhost:4010`.
2. Опишите TypeScript интерфейсы (Owner, EventType, Slot, Booking) согласно схеме из `docs/calendar.tsp`.
3. Напишите кастомные хуки для API:
   - `usePublicEventTypes()`, `useAvailableSlots(eventTypeId, from, to, timezone)`, `useCreateBooking()`
   - `useOwnerProfile()`, `useOwnerEventTypes()`, `useCreateEventType()`, `useUpdateEventType()`
   - `useOwnerBookings()`, `useCancelBooking()`

## Шаг 5: Реализация интерфейса Владельца (Owner)
**Задача:** Сделать страницы управления для владельца.
1. **Типы событий (`/owner/event-types`):** Вывод списка в виде карточек. Добавьте модальное окно (Dialog) с формой для создания нового `EventType` (поля `name`, `description`, `durationMinutes`). Реализуйте редактирование существующих типов.
2. **Предстоящие бронирования (`/owner/bookings`):** Отображение списка бронирований (с пагинацией, если необходимо). Добавьте кнопку отмены бронирования (отправка POST на `/owner/bookings/{bookingId}/cancel`).

## Шаг 6: Реализация интерфейса Гостя (Public / Guest)
**Задача:** Реализовать флоу бронирования встречи.
1. **Главная страница (`/`):** Список всех доступных типов событий. По клику переход на страницу конкретного типа события.
2. **Выбор слота (`/book/:eventTypeId`):**
   - Отобразите компонент календаря (shadcn `Calendar`) для выбора даты.
   - При выборе даты запрашивайте слоты через `useAvailableSlots` (с `from` и `to` начала и конца выбранного дня в UTC, не забудьте передать `timezone` клиента).
   - Выведите свободные слоты (`isAvailable: true`) в виде кнопок с указанием времени начала.
3. **Оформление брони:** 
   - По клику на слот показывайте форму (Имя, Email).
   - При сабмите отправляйте `POST /public/bookings` (поля: `eventTypeId`, `startAt`, `guestName`, `guestEmail`). *Примечание: `endAt` вычисляется сервером.*
   - При конфликте (409) или ошибках (400) показывайте Toast уведомление.
   - При успехе показывайте сообщение с полученным `guestCancelToken` (и, опционально, кнопкой "отменить для теста").

## Шаг 7: Финализация и полировка UI
**Задача:** Довести интерфейс до production-like состояния.
1. Обеспечьте адаптивность всех страниц (Mobile First).
2. Настройте состояния загрузки (скелетоны или спиннеры для компонентов, пока данные грузятся через React Query).
3. Добавьте обработку пустых состояний (например, "Нет доступных слотов на эту дату", "Нет предстоящих бронирований").
4. Проверьте отсутствие ошибок типизации (TypeScript strict mode) и протестируйте полный флоу бронирования в браузере.
